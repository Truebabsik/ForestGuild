# ForestGuild — правила для агентов

Unity 6000.6.6f1, URP 17.6.0.0, Input System 1.20.0 (только новый). Unity-проект лежит в `FG/`,
документы — в `docs/` в корне репозитория. Игра: фэнтези-деревня на краю магического леса; срез —
цикл суток с двумя отрядами, походом по часам, вечером, ночью и волной на 21-й день.

Документация: `docs/design.md` — гейм-дизайн (что за игра и зачем); `docs/architecture.md` —
архитектура, слои, формат CSV и **полные** правила; `docs/ui.md` — экраны UI и таблица сверки §14
«что реализовано»; `docs/decisions.md` — журнал решений (ADR); `docs/current/` — текущие задачи;
`docs/archive/` — завершённые.

## Инструментарий

Скиллы — в `.dsh/skills`, вспомогательные инструменты — в `.dsh/tools`. Работа с живым Editor — только
после скилла `unity-pipeline`.

Быстрые команды из корня:

- проверки ядра: `dotnet run --project tools/sim -- --selfcheck` (должно быть «все проверки прошли (36)», код 0);
- пассивный прогон леса: `dotnet run --project tools/sim -- --days 21` — таблица дней;
- открыть редактор: `Start_editor.bat` (или `unity open FG --args -automated`).

## Критичные правила

Нарушение любого из них ломает проект **молча**.

1. **Сцена — только через живой Editor** (`unity_status` → `unity_command` / `unity_eval`). Editor —
   источник правды о сцене.
2. **Не править `.unity` / `.prefab` / `.asset` на диске**, пока Editor запущен, — правка молча
   перезапишется.
3. **После мутаций сцены — сохранять явно** (`MarkSceneDirty` → `SaveScene`) и проверять запись по
   файлу на диске. `isDirty` врёт: создание объектов через `unity_eval` его не поднимает, поэтому
   `isDirty == False` не значит, что сцена не менялась.
4. **Input System — только новый**: `Keyboard.current`, Input Actions. Легаси `Input.GetAxis` бросает
   `InvalidOperationException` (`activeInputHandler: 1`).
5. **Unity 6 API**: `Rigidbody.linearVelocity`, а не `velocity`; `Object.FindAnyObjectByType`, а не
   `FindObjectOfType`.
6. **Скрипты — в `FG/Assets/Scripts/`**, `asmdef` не заводить: весь код идёт в `Assembly-CSharp`.
   Слои: `Core/` — чистое ядро без `using UnityEngine`, `Game/` — адаптеры и экраны UI Toolkit.
7. **Числа — в CSV**, в `FG/Assets/StreamingAssets/Data/` (15 справочников), не в коде. Новое правило
   баланса проверяется прогоном в `tools/sim`, а не «на глаз» в Play Mode.
8. **Проверять, а не заявлять**: читать состояние (вывод команды, `resolvedStyle`, скриншот) и
   показывать его. Доказательство раньше утверждения.
9. **Живой Editor — через скилл `unity-pipeline`**, до первой команды. Обязательные привычки:
   `set_autotick` (иначе `recompile` и тесты висят без фокуса); пара `recompile` → `recompile_status`
   вместо «поспал и понадеялся»; `script run` для любого C# длиннее одной строки (файл на диске **вне**
   `Assets/`, поэтому правка не тянет импорт), `unity_eval` — для однострочников. **Play Mode при
   потере фокуса не тикает даже с автотиком** — кадры гонять `Physics.simulationMode = Script` +
   `Physics.Simulate`, `FixedUpdate` звать рефлексией (ADR-0039).
10. **Документы — часть продукта.** Меняешь экран или число — в том же коммите поправь `docs/*.md`
    (для экранов — ещё и строку в таблице `ui.md` §14). Документ, который обещает несуществующее хуже
    отсутствующего.

## Грабли окружения

- **`Temp/` Unity стирает сама.** Временное — только временное: всё, что должно пережить сессию,
  кладём в git. Скриншоты для документов копируются из `FG/Temp/` в `docs/images/`.
- **PowerShell читает UTF-8 без BOM как cp1251.** Круговое «прочитал → записал» портит русский текст:
  `Map.uxml` уже ловил двойную кодировку («СВОБОДНЫЕ» → «РЎР’РћР‘РћР”РќР«Р•»). Правило: текстовые файлы
  править редактором (`read`/`edit`), а не `Get-Content | Set-Content`. Если скрипт всё же пишет файл —
  только `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))`.
- **`Set-Content -Encoding UTF8` в Windows PowerShell 5.1 пишет BOM**, и он уезжает в заголовок коммита.

## Грабли автотестов в Editor

- **Play Mode без фокуса не тикает** (ADR-0039): «подождал и проверил» показывает состояние до нажатия.
- **Пробы UI — файлом** в `FG/AgentScripts/` и только через
  `unity command script run --file AgentScripts/X.cs --entry X.Run`. Вызов приватных методов — рефлексией.
- **После правки C# всегда** `recompile` → `recompile_status`, затем `editor.playmode stop` →
  `editor.playmode start`: Play Mode держит старую сборку, и UI показывает прошлую версию.
- **Скриншоты**: `capture game_view --output-path Temp/xxx.png`, потом копировать в
  `docs/images/ui/step1/`. Смотреть глазами, но числа (размеры, прозрачность, тексты) брать из
  `resolvedStyle`/полей — по картинке в 720p легко принять норму за баг.
- **Проверять данные, а не только картинку**: смена CSV подхватывается при старте Play Mode (горячей
  перезагрузки таблиц нет), поэтому после правки данных нужен перезапуск Play Mode.

## Цикл задачи

Создать `docs/current/YYYY-MM-DD-<слаг>/plan.md` → вести чеклист, значимые решения писать сразу в
`docs/decisions.md` → по завершении дописать `result.md` (что сделано и **чем проверено**) и перенести
папку в `docs/archive/`.

Коммит — одна законченная мысль. Сообщения на русском или английском, но одинаково в пределах ветки.

Язык: общение и документация — русский; код и идентификаторы — английский.
