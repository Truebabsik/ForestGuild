# Dwarf — правила для агентов

Unity 6000.6.6f1, URP 17.6, Input System 1.20 (только новый). Ранняя стадия: одна сцена, один игровой скрипт.

Документация: `docs/design.md` — гейм-дизайн; `docs/architecture.md` — архитектура, структура и **полные** правила;
`docs/ui.md` — **UI: экраны цикла суток, отряды-пресеты, карты событий вылазки**;
`docs/decisions.md` — журнал решений (ADR); `docs/textures.md` — **библиотека текстур: каталог, шортлист и конвейер**;
`docs/models.md` — **каталог моделей: что есть, где стоит и как добавить новую**;
`docs/animation.md` — **анимация: риг кузнеца (ARP-риг из бэкапа), кисти и двуручный хват, ходьба, ретайминг, экспорт**;
`docs/current/` — текущие задачи; `docs/archive/` — завершённые.

## Критичные правила

Нарушение любого из них ломает проект **молча**.

1. **Сцена — только через живой Editor** (`unity_status` → `unity_command` / `unity_eval`). Editor — источник правды о сцене.
2. **Не править `.unity` / `.prefab` / `.asset` на диске**, пока Editor запущен, — правка молча перезапишется.
3. **Input System — только новый**: `Keyboard.current`, Input Actions. Легаси `Input.GetAxis` бросает `InvalidOperationException` (`activeInputHandler: 1`).
4. **Unity 6 API**: `Rigidbody.linearVelocity`, а не `velocity`.
5. **Скрипты — в `Assets/Scripts/`**, asmdef не заводить: в проекте их нет, весь код идёт в `Assembly-CSharp`.
6. **После мутаций сцены — сохранять явно**: `MarkSceneDirty(scene)` → `SaveScene(scene)`, затем проверить запись по `.unity` на диске. **`isDirty` врёт**: создание объектов через `unity_eval` его не поднимает (нет регистрации в Undo), поэтому `isDirty == False` **не значит**, что сцена не менялась. Уже привело к потере всей расстановки пропов кузницы. Ссылки на материалы в `.unity` ищутся по `guid` из `.mat.meta`, а не по имени — по имени они «не найдены» на живых ссылках.
7. **Проверять, а не заявлять**: читать состояние (`get_component_properties`, `unity_eval`, `console`) и показывать вывод. Доказательство раньше утверждения.
8. **Текстуры — из библиотеки `Resources/textures/`**, **вне `Assets/`**, и она в `.gitignore`. Не переносить её внутрь `Assets/` под именем `Resources`: это служебная папка Unity, её содержимое целиком уезжает в билд. Нормали брать **только** из `*_normalOGL` / `*_normalogl` — файл `*_normal` содержит перевёрнутый зелёный канал и даёт вдавленные выпуклости. Карты искать без учёта регистра. Каталог и шортлист — `docs/textures.md`, конвейер — скилл `.dsh/skills/unity-texture-import`.
9. **Пропы: генерация 50k, геометрию не трогать.** Модель приходит от генератора с бюджетом 50 000 треугольников; конвейер по умолчанию **жмёт только текстуры** (`--max-tris 0`). Децимация — исключение, и только если planar dissolve снимает больше 80 %: у горна он снял 49 %, и при 40 000 форма разъехалась. Исходники — в `Resources/models/origins/`, вне `Assets/`, оригиналы не трогать. **Реф — до генерации**: `Resources/models/refs/<имя>.jpg` (2048²) + `.txt` с промптом, генератором, датой и целевым размером; пара, чья модель пришла, — в `refs/Done/`. Реф мерить `measure_ref.py` **до** генерации: конвейер пинует одну ось, поэтому отношение сторон на картинке решает, влезет ли предмет. Полные правила — `.dsh/skills/unity-model-optimize`, порядок «реф → модель → каталог» — `.dsh/skills/unity-model-catalogue`. **Любой прогон Blender — после скилла `.dsh/skills/blender-headless`**: там контракт запуска (`--background --factory-startup --python-exit-code 1`), таблица ловушек 5.2 и пресет обмена FBX с Unity; без него прогон «отчитывается успехом», не записав файл.
10. **Каталог моделей ведётся вместе с проектом.** `docs/models.md` (описание, габариты, где стоит, состояние) и лист `docs/images/models_sheet.jpg` обновляются **тем же коммитом**, что и добавленная, заменённая, удалённая или перемасштабированная модель. Каталог, который отстаёт от проекта, хуже отсутствующего: по нему принимают решения. Для текстур действует то же правило — `docs/textures.md`. Порядок приёмки модели, ловушки таблицы и чеклист — скилл `.dsh/skills/unity-model-catalogue`.
11. **Работа в живом Editor — через скилл `.dsh/skills/unity-pipeline`**, читать до первой команды. Без него теряются три вещи, и каждая уже стоила времени: `set_autotick` (без него `recompile` и тесты висят, когда редактор не в фокусе); пара `recompile` → `recompile_status` вместо «поспал пять секунд и понадеялся», что код пересобрался (`run_tests` → `test_status` — то же); `run_script` для любого C# длиннее одной строки — файл на диске **вне** `Assets/`, правка не тянет импорт, а `unity_eval` остаётся однострочникам. **Play Mode при потере фокуса не тикает даже с автотиком** — кадры гонять `Physics.simulationMode = Script` + `Physics.Simulate`, `FixedUpdate` звать рефлексией (ADR-0039).

## Грабли окружения

- **`Temp/` Unity стирает сама.** 17.10.2026 редактор очистил папку посреди сессии: вместе с логами
  и скриншотами замеров пропали два скрипта, лежавшие там в единственном экземпляре. Временное —
  только временное: всё, что должно пережить сессию, кладём в git. Скрипты-помощники живут в
  `.dsh/tools/` (порядок запуска и трапы — его `README.md`), полный факт — `docs/architecture.md`.
- **PowerShell 5.1 читает файл без BOM как cp1251.** Скрипты проекта — UTF-8 без BOM, а политика
  выполнения запрещает запуск `.ps1` напрямую, поэтому запуск только через
  `[scriptblock]::Create([IO.File]::ReadAllText($p, [Text.Encoding]::UTF8))`. `Parser::ParseFile` на
  таком файле выдаёт ложное «The string is missing the terminator» — это кодировка, а не код.
  Обратная сторона той же ловушки: `Set-Content -Encoding UTF8` **пишет BOM**, и он уехал в заголовок
  коммита — текст для git собирать через
  `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))`.

## Грабли автотестов в Editor

- **Команды `simulate_key` в проекте нет.** В пакете `com.unity.pipeline` только `editor_play`,
  `editor_stop`, `editor_pause`, `editor_focus`. Ввод инжектится вручную через Input System.
- `editorInputBehaviorInPlayMode` живёт в `UnityEngine.InputSystem.InputSystem.settings`,
  **не** в `EditorSettings`, и enum `EditorInputBehaviorInPlayMode` не вложен в `InputSettings`.
  Дефолт — `PointersAndKeyboardsRespectGameViewFocus`: без фокуса Game View ввод не доедет.
  Для автотеста переключить на `AllDeviceInputAlwaysGoesToGameView` и **вернуть назад**.
- `backgroundBehavior` сбрасывает устройства, когда Editor не в фокусе.
- **`Application.runInBackground = true` перетирает инжектированную клавишу каждый кадр** —
  инъекция выживает 1–2 кадра, и на этом легко построить ложный вывод. Для честного теста
  писать приватное `_moveInput` напрямую из `LateUpdate` пробника, а не жать клавишу.
- **Мерить на границах игрового цикла**: `EditorApplication.update` срабатывает до игрового
  цикла, поэтому `Rigidbody.linearVelocity` оттуда читается как `(0,0,0)` у едущего тела.
  Правду дают `FixedUpdate` и `LateUpdate` пробника.
- После теста: вернуть изменённые настройки, удалить пробники и выйти из Play Mode.

## Цикл задачи

Создать `docs/current/YYYY-MM-DD-<слаг>/plan.md` → вести чеклист, значимые решения писать сразу в `docs/decisions.md` →
по завершении дописать `result.md` (что сделано и **чем проверено**) и перенести папку в `docs/archive/`.

Язык: общение и документация — русский; код и идентификаторы — английский.
