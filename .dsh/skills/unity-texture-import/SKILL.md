# Импорт текстур из библиотеки в Unity

## Рабочий процесс проекта — читать первым

Исходники лежат в `Resources/textures/` — **вне `Assets/`** (ADR-0009). Имена карт в паках
гуляют по регистру: `normalogl` и `normalOGL` встречаются в одной библиотеке. Нормали брать
**только** из `*_normalOGL` / `*_normalogl`: файл `*_normal` содержит перевёрнутый зелёный
канал и даёт вдавленные выпуклости вместо выпуклых.

Каталог библиотеки, шортлист и таблицы размеров тайла — `docs/textures.md`.

```powershell
python .dsh/skills/unity-texture-import/scripts/convert_texture.py `
    --material Stylized_StoneTiles_02 --name stonetiles02 --size 1024 --mask-size 512
```

| Ключ | Что |
|---|---|
| `--material` | селектор материала: последний фрагмент обязан совпасть с именем папки или быть его суффиксом после `_` |
| `--name` | базовое имя выходных карт |
| `--size` | размер color и normal |
| `--mask-size` | размер карты масок (её можно мельче) |
| `--rotate` | повернуть исходник, `90` / `180` / `270` |

## Что получается

| Вход | Выход | Что делает |
|---|---|---|
| `*_basecolor.jpg` | `<имя>_color.jpg` | сжатие, JPEG q92, **sRGB** |
| `*_normalOGL.jpg` | `<имя>_normal.png` | `NormalMap`, **не sRGB** |
| `*_metallic.jpg` | `<имя>_masks.png` | `R = metallic` |
| `*_ambientocclusion.jpg` | | `G = AO` |
| `*_roughness.jpg` | | `A = 255 − roughness` |
| `*_height.jpg` | — | выбрасывается, URP Lit его не читает |

**Одна карта масок на два слота.** URP Lit берёт металличность и гладкость из
`_MetallicGlossMap` (R и A), а затенение — из `_OcclusionMap` (G). Один и тот же файл
назначается в оба слота.

## Настройки импортёра обязательны

```csharp
ti.textureType = TextureImporterType.NormalMap;   // для карты нормалей
ti.sRGBTexture = false;                           // для нормалей И для масок
ti.alphaSource = TextureImporterAlphaSource.FromInput;  // без этого гладкость молча пропадёт
ti.wrapMode = TextureWrapMode.Repeat;
```

`alphaSource` — самый коварный: без него Unity решает, что альфа не нужна, и гладкость
исчезает **без ошибки**. Ассет выглядит целым.

## Материал URP Lit

```
_BaseMap          <- <имя>_color.jpg
_BumpMap          <- <имя>_normal.png
_MetallicGlossMap <- <имя>_masks.png
_OcclusionMap     <- <имя>_masks.png
_BumpScale        = 0.5
```

Ключи: `_NORMALMAP`, `_METALLICSPECGLOSSMAP`, `_OCCLUSIONMAP`.

**`_BumpScale = 1` — слишком много.** С исходной нормалью этих паков поверхность выглядит
надутой. Рабочее значение — **0.5**. При уменьшении тайла рельеф надо ослаблять ещё:
тот же нормализованный рельеф на меньшем расстоянии даёт более крутой наклон.

## Тайлинг

```
tiling = размер грани / реальный размер текстуры
```

**По обеим осям** — иначе текстура растягивается по высоте. Размер текстуры в метрах
определяется **числом блоков в ряду**, а не ощущением: посчитать блоки и умножить на
желаемый размер блока. У `Stone_01` их 5, у `StoneTiles_02` — 6, у `StoneTiles_01` — 9.

Тайлинг задаётся на **материале**, а не на объекте, поэтому он глобальный на всю грань.
Если стена разрезана на сегменты вокруг проёма, каждому сегменту нужен свой материал
с посчитанным `offset` — иначе рисунок кладки начнётся заново и на стыке будет шов
(ADR-0014).

## Направление волокна задаёт меш, а не текстура

Unity-куб всегда кладёт `U` вдоль первой оси грани. На длинных гранях бруса `U` идёт
по длине, поэтому текстура с волокном по `V` ложится **поперёк** и на рендере читается
плотной поперечной штриховкой. Лечится `--rotate 90`.

**Поворот нормали надо проверять, а не предполагать** — нормаль это векторное поле.
При повороте на 90° против часовой поле высот становится `h'(u,v) = h(v, 1-u)`, откуда
`n' = (-n_y, n_x, n_z)`, то есть `R' = 255 − G`, `G' = R`, синий не тронут:

```
4 x 90deg vs original: max channel diff = 0         (поворот обратим)
blue of rotated == blue of plain transpose : True   (синий не тронут)
R' == 255 - G_plain                        : True
G' == R_plain                              : True
```

## Карты-пустышки

**Размер файла — диагностика.** Карта масок в 1.8 КиБ вместо обычных 200–300 означает
пустышку в исходниках. Конвейер печатает `NOTE` на каждую плоскую карту, но проверять
размер вывода дешевле, чем потом искать, почему поверхность выглядит не так.

Отдельный замер по всей библиотеке: **39 из 54** материалов имеют плоскую карту `metallic`,
**12** — плоский `ao`, **8** — плоский `roughness`. Плоский `metallic` безобиден
(диэлектрик). Опасен **плоский `roughness` = 255**: он выглядит как данные, а означает
гладкость 0, то есть полностью матовую поверхность. Вся пачка `Stylized_GrassAndDirt`
отдаёт `roughness` = 255 и `ao` = 255 — автор их просто не заполнял.

## Грабли

**Селектор по подстроке опасен.** `Wood_01` как подстрока входит в имя папки
`Materials_Stylized_stone_wood_01`, поэтому «гибкий» поиск вернул весь пак из девяти
материалов и упал на неоднозначности. Последний фрагмент селектора обязан совпадать
с именем папки материала или быть его суффиксом после `_`.

**Численный тест швов переоценивает проблему.** Замеры краёв `Stone_01` давали мягкий шов,
и это вызывало опасения. **На рендере швов не видно ни у одного кандидата.** То же
с зеркальным `wrapMode`: опасение, что симметрия будет видна, не подтвердилось — на
регулярной кладке отражение сливается с рисунком. Критерий — визуальный тест 2×2 тайла,
а не число.

**Камера должна стоять между полом и потолком.** Рендер пола сверху с высоты 4.2 м при
потолке 2.6 м показал **верхнюю грань коробки потолка**, а не пол.

**Один кадр — не доказательство.** Первый рендер комнаты после `SaveScene` вернул кадр
с небом вместо интерьера; повторный рендер того же кадра дал правильную картинку.
Причина не установлена. Не доверять одиночному кадру, повторять.
