## 3. Задачи по порядку

### P0 — убедиться, что бой в Unity не сломан

**T1. Прогон боя в Play Mode после правок ядра.** — **сделано 2026-11-10.**

Что: старт сценария «ПОХОД В ЛЕСУ» → встреча со стаей → бой → туша/ранение; несколько боёв подряд,
проверка HP, HUD и времени в минутах. Пробник — `FG/AgentScripts/DriveBattle.cs` (`Start`, `Fight`,
`Auto`, `Wound`).

Доказательства: `decision=Encounter title=[ВСТРЕЧА: Осколочник] art=shard-search`, после боя
`Осколочник падает. / бой — победа`, HP `brunni 54/54`, `skadi 45/45`; `Auto` — 4 встречи, 2 победы,
1 поражение, `hilda 0/36 Wounded`, `orn 0/54 Wounded`; `Wound` — `decision=Wounded title=[РАНЕН: Брунни]`,
варианты «нести / оставить»; `hud=[здоровы 6/8]`, `hourLabel=[осталось 410 мин]`.
Скриншот карточки ранения — `docs/images/ui/step1/battle-wound.png`. `--selfcheck`: 67 проверок, код 0.

**Найдено и исправлено в ходе T1:**

1. **Стая собиралась из разных видов.** Карточка «Осколочник (стая из 2)» (по `pack[0]`), бой
   «Искромёт (стая из 2)» (по самой быстрой), дроп — только с одного вида. Теперь `PickPack` берёт
   один вид, размер — не больше, чем этого вида в зоне. Проверка: «encounter pack is one species» (67-я).
2. **HUD не обновлялся в походе:** после боя «здоровы 8/8» при двух выбитых. `ExpeditionScreen.Changed`
   → `HudView.Update`.
3. **«осталось N мин» отставало на весь бой:** `Choose` не звал `UpdateHour`, метка показывала 420 при 410.


### P1 — бой должен быть виден (главное)

**T2. Карточка боя.** — **сделано 2026-11-10, доработано: рассказ построчно.**
Новый `DecisionKind.Battle`: модал — арт `_attack`, строки раскрываются по одной (650 мс), слова о
состоянии людей, кнопка «дальше». Строки собирает `Battle.Resolve`: строка на каждую атаку и промах,
засада отдельным нарративом в начале. По наказу карточка не держит поход.

Доказательства: `AmbushStory` → `lines=1 body=[Пепельный вор застаёт отряд врасплох.]`,
`RevealAll` → 14 строк, `Metrics: viewH=505 contentH=505 offset=0`; `AutoFight` (наказ «бей») — бой
прошёл без карточек. Проверки «battle tells its story without numbers», «ambush has its own narrative»,
«battle card waits only when the encounter is asked» (70/70).
Скриншот: `docs/images/ui/step1/battle-card.png`.

**T3. Арт `_attack` в момент удара.** — **сделано вместе с T2.** `ShowMonsterDecision` выбирает
`search` для встречи, `attack` для боя, `dead` для туши. На скриншотах `shard-attack` и `bone-attack`.

**T4. HP людей словами.** — **сделано 2026-11-10.** `Battle.HpWord` — один словарь на весь интерфейс
(«в порядке / в ссадинах / ранен / тяжело ранен / на ногах не стоит»), в `Ui.HpWord` учтены
`погиб` и ранение-как-выбитый. Места: карточка боя, **доска утра** (строка состава), **Сбор**
(плитка человека), **вечер** (раненые с именем и словом).

Доказательства: доска — `squadLines=[Брунни — тяжело ранен, Скади — ранен, Хильда — в порядке]`;
Сбор — `words=[ранен | … | тяжело ранен | …]`; вечер — `lines=[· Раненые: Лея — на ногах не стоит]`;
проверка «hp is a word with exact steps» (71/71). Скриншоты: `board-hp.png`, `muster-hp.png`, `evening-hp.png`.

Досье зоны людей не показывает (оно про зону), поэтому третье место — Сбор, где как раз выбирают,
кого послать.

**T5. Риск для стаи.** — **сделано 2026-11-10.** Оценка уже шла по всей пачке, но слово у порога
врало: на 120 прогонах выходило 87,5 % там, где честно 83,8 %, и «надёжно» превращалось в
«почти наверняка». Теперь `Battle.Estimate` гоняет 400 прогонов (~6 мс) — ошибка ~2 п.п.
Проверки: «risk word counts the whole pack» (один костяной бегун — «почти наверняка», двое —
«рискованно»; три вора заметно хуже одного), «risk word is a word, never a number» (только четыре
слова, ни цифр, ни процентов), «encounter fight note is a risk word».

Доказательство в UI: `one=[ВСТРЕЧА: Пепельный вор → почти наверняка]`
`three=[ВСТРЕЧА: Пепельный вор (стая из 3) → надёжно]`.
Скриншот: `docs/images/ui/step1/pack-risk.png`.

### P2 — зафиксировать баланс

**T6. Калибровка h1/h3 и болотника.** Менять по одному числу, мерить `--curve` (4000 боёв) и
`--battle`; h2 51,2 % держать в 45–55.
Готово, когда: h1 ≤10, h2 45–55, h3 75–85, болотник в одном порядке с осколочником; числа записаны в `design.md`.

**T7. Точка 21 дня.** Пересчитать и зафиксировать (сейчас 14 / волна 10 / 0): либо числа тварей,
либо частокол/волна. Записать в `design.md` и в проверку.
Готово, когда: `--days 21` даёт записанную тройку, проверка её утверждает.

**T8. Несение выбитого: −3 слота.** Довести до ADR-0043 и проверить в походе.
