# Бой в Unity: видимость и проверка — итог

Дата: 2026-11-10. Статус: T1–T3 плана сделаны; T4–T10 (HP вне боя, риск для стаи, калибровка,
точка 21 дня, долги) — в работе. План — `plan.md`.

## T1 — прогон боя после правок ядра

Пробник `FG/AgentScripts/DriveBattle.cs` (`Start`, `Fight`, `Next`, `Auto`, `AutoFight`, `Wound`)
ведёт настоящий поход через приватный тик экрана. Прогон нашёл три дефекта, все исправлены:

1. **Стая собиралась из разных видов.** Карточка «Осколочник (стая из 2)», бой «Искромёт (стая из 2)»,
   дроп — только с одного вида. Теперь `PickPack` берёт один вид, размер ограничен числом этих тварей
   в зоне; проверка «encounter pack is one species».
2. **HUD не обновлялся в походе** («здоровы 8/8» при двух выбитых). `ExpeditionScreen.Changed` →
   `HudView.Update`.
3. **«осталось N мин» отставало на весь бой** (420 при 410). `Choose` теперь зовёт `UpdateHour`.

Доказательства: `hud=[здоровы 6/8]`, `hourLabel=[осталось 410 мин]`, `hilda 0/36 Wounded`,
`orn 0/54 Wounded` после трёх боёв; карточка ранения — `docs/images/ui/step1/battle-wound.png`.

## T2 — карточка боя

- `Battle.Resolve` собирает рассказ в 3–5 строк: засада → кто бьёт → кого достало → исход → HP словами.
  Счётчики `Hits/DamageDealt/DamageTaken` на бойце — источник строк, цифры в текст не попадают.
- `Battle.HpWord` — единственная форма HP, которую видит игрок («в порядке / в ссадинах / ранен /
  тяжело ранен / на ногах не стоит»).
- `DecisionKind.Battle` + `Expedition.LastBattle`: карточка «БОЙ: имя», арт `_attack`, одна кнопка
  «дальше». По наказу (не `Ask`) карточка не держит поход — бой идёт без паузы.
- UI: `UsesMonsterArt` включает бой, `ShowMonsterDecision` выбирает `search` / `attack` / `dead`.

Доказательства в Play Mode:

| Что | Результат |
|---|---|
| Победа | `БОЙ: Осколочник`, `art=shard-attack`, тело: «Брунни бьёт. Осколочник падает. Брунни — в порядке, Скади — в порядке.», кнопка «дальше» |
| Поражение | `БОЙ: Костяной бегун`, `art=bone-attack`, 4 строки: «Брунни бьёт; Скади прикрывает. / Тварь достаёт Брунни. / Отряд смят: кто-то не поднимется. / Брунни — на ногах не стоит, Скади — на ногах не стоит.» |
| Дальше | «дальше» → туша (победа) или «РАНЕН: Брунни» (поражение) |
| Наказ «бей» | `AutoFight`: бой прошёл с уроном (`brunni 50/54`, `skadi 37/45`), карточек боя **0** — паузы нет |

Скриншоты: `docs/images/ui/step1/battle-card.png` (полный рассказ боя с засадой).

## Итерация 3 — рассказ боя построчно

По просьбе владельца бой стал сценой: строка на каждую атаку героя и твари, включая промахи,
и отдельный нарратив засады.

- `Battle.Resolve` пишет события, а не выжимку: «Пепельный вор застаёт отряд врасплох.» →
  «Пепельный вор бьёт из засады — Скади не успевает прикрыться.» → «Брунни бьёт, но промахивается.» →
  «Скади бьёт — Пепельный вор дрогнул.» → «Пепельный вор падает.» → «Брунни — в ссадинах, Скади — ранен.»
  Имена не склоняются: «бьёт — Осколочник дрогнул» вместо «бьёт Осколочника» (падеж вида не выводится из данных).
- В `BattleResult` добавлена `Summary` — короткая выжимка для общего лога похода, чтобы бой не заливал лог.
- UI: строки в `ScrollView` (`monster-lines`), каждая раскрывается через 650 мс; арт `_attack` для боя
  уменьшен до 120, чтобы 14 строк влезали целиком; полоса прокрутки скрыта, прокрутка — только если
  рассказ длиннее окна. По наказу карточка не держит (бой без паузы).

Доказательства: `AmbushStory` находит бой с засадой и замирает на первой строке
(`lines=1 body=[Пепельный вор застаёт отряд врасплох.]`), `RevealOne` добавляет ровно одну строку,
`RevealAll` даёт `lines=14`; `Metrics`: `viewH=505 contentH=505 offset=0` — весь рассказ виден,
начиная с засады.

## Проверки

`dotnet run --project tools/sim -- --selfcheck` → **70 проверок, код 0**. Новые:
«battle tells its story without numbers» (строка на атаку, слова об исходе, ни одной цифры),
«ambush has its own narrative» (первая строка — обнаружение, есть удары «из засады»),
«battle card waits only when the encounter is asked» (карточка ждёт только при `Ask`), плюс
«encounter pack is one species» из T1.
