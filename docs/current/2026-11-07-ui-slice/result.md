## Итерация 2 — связность, ночь, визуал

Сделано после первого прогона:

- **Один человек — одно дело.** `DayPlan.IsBusy` + `RosterPanel.SetBusy`: занятый житель гаснет и не выбирается. Отряд убирается кнопкой «×», работники деревни — общей кнопкой.
- **Лимит два отряда** (`DayPlan.MaxParties = 2`), третья попытка даёт тост «Больше 2 отрядов деревня не поднимет».
- **Намерение отряда** выбирается кнопками «Сбор / Избегание / Чистка» и уходит в `PartyAssignment.Behavior`.
- **Работы в деревне**: «В ДЕРЕВНЮ» отправляет жителя на частокол, 1 человеко-день = +2 прочности (`DayFlow.RepairPalisade`).
- **Деревня на карте**: узел с иконкой, соединён ребром с зоной-воротами, состояние — прочность частокола.
- **Ночь объясняет себя**: на каждую зону с тварями строка «N твар., съедено корма X, кристаллов Y, голодных Z», в конце — «В лесу тварей: N, кристаллов на земле: M».
- **Иконки зон** (Agnes, 7 штук: шесть зон + деревня), сжаты до 128×128, лежат в `FG/Assets/UI/Art/Icons/`.
- Сообщения переехали из полноэкранного отчёта в тост над нижней панелью.

Проверено: `dotnet run --project tools/sim -- --selfcheck` → **14 проверок, код 0** (добавлены «village workers repair palisade» и «night report explains feeding»); в Play Mode пройден план «два отряда + 1 в деревне», третья попытка отбита лимитом, день закончен — отчёт ниже.

## Заметки на будущее

- `UIDocument.panelSettings`, назначенный сеттером из скриптовой сборки сцены, **не сериализуется** (`m_PanelSettings: {fileID: 0}`) — экран чёрный. Ставить через `SerializedObject` и сохранять сцену.
- `unity command script run` (не `run_script`), `editor.playmode start/stop` (не `editor_play`), `set_auto_tick --enabled`.
- USS и текстуры подхватываются только после `AssetDatabase.Refresh`: правки на диске при неактивном редакторе не импортируются сами.
