# ForestGuild — архитектура

Статус: черновик v0.1. Решения, которые дорого откатывать, — в `docs/decisions.md` (ADR-0001, ADR-0002).

## 1. Слои

Четыре слоя, каждый знает только про соседа снизу.

| Слой | Что внутри | Зависит от Unity |
|---|---|---|
| **Данные** | CSV-справочники: все числа, все формулы-коэффициенты | нет |
| **Ядро** | чистая модель: лес, сутки, вылазка, бой, навыки, крафт | **нет** |
| **Адаптеры** | сцена, ввод, UI, отрисовка, сохранения | да |
| **Инструменты** | валидатор таблиц, консольный прогон N дней | нет |

Правило, за которое отвечает вся архитектура: **числа меняются без компиляции, структура меняется с компиляцией.** Всё, что в таблице, правится на ходу; всё, что в коде, проходит через компилятор и тесты.

Ядро не содержит `using UnityEngine` — ни одного. Это проверяется тестом (`Core` не должен ссылаться на `UnityEngine`), а не обещанием.

## 2. Структура папок

```
Assets/
  StreamingAssets/
    Data/              # CSV-справочники: единственный источник чисел
      tuning.csv
      items.csv
      zones.csv
      zone_resources.csv
      beasts.csv
      zone_beasts.csv
      drops.csv
      skills.csv
      traits.csv
      professions.csv
      roster.csv
      stations.csv
      recipes.csv
      recipe_quality.csv
      zone_lore.csv
      scenarios.csv
      scenario_parties.csv
  Scripts/
    Core/              # чистая модель, без UnityEngine
      Data/            # типы строк таблиц и загрузчик
      Sim/             # день, час, лес, отряд, бой
    Game/              # MonoBehaviour-адаптеры: сцена, UI
tools/
  sim/                 # .NET-консоль: прогон 21 дня, валидация, отчёты
```

`tools/sim` подключает файлы ядра напрямую (`<Compile Include="../../Assets/Scripts/Core/**/*.cs" />`), поэтому симуляция и игра гоняют **один и тот же код**, а не две реализации.

## 3. Формат таблиц

- CSV, **UTF-8** (BOM допускается), разделитель **`;`**, десятичная **точка**.
- Первая непустая строка — заголовки. Первая колонка — `id`.
- Строки, начинающиеся с `#`, игнорируются (комментарии и пустые разделители).
- `id` — только `snake_case` из ASCII. Русский текст живёт в колонке `name`, не в `id`: кириллица в ключах — это гарантированная проблема с кодировками и диффами.
- Типы колонок объявлены в схеме загрузчика: `int`, `float`, `string`, `id`, `id_levels`, `id_list`, `bool` (`0`/`1`), `enum` со списком допустимых значений.
- Списки в ячейке — **единственная мини-грамматика**: `a:1|b:2`. Больше никаких выражений в таблицах.

## 4. Справочники

| Файл | Колонки |

Ресурс и предмет — **одна сущность**: трава из леса, ингредиент и груз в мешке — одна строка `items.csv`.

## 5. Валидация

Загрузчик не «старается» — он падает.

- Неизвестный `id` во внешнем ключе — исключение с таблицей, номером строки и именем колонки.
- Неизвестный `enum`-вариант, битое число, лишняя колонка, пустой обязательный — то же самое.
- `schema_version` в `tuning.csv`; при несовпадении загрузчик отказывается стартовать.
- В игре ошибка показывается красным оверлеем с текстом исключения; координата `файл:строка:колонка` пока есть только у ошибки числа колонок (`CsvReader`), у внешних ключей — только имя файла и сообщение. В консоли — ненулевой код возврата.

Причина жёсткости: таблица, которая молча не применилась, хуже отсутствующей. Этот проект уже терял расстановку сцены из-за «тихого» состояния — повторять не будем.

## 6. Ядро

- **Детерминизм.** Один сид на прогон, весь случай — через переданный `Rng`. Никаких `DateTime.Now`, `UnityEngine.Random`, `Guid.NewGuid` в ядре.
- **Время — счётчики.** `Day` и `Hour` — целые поля, а не системные часы. Отсюда бесплатные тесты: 21 день — это 21 вызов `AdvanceDay()`.
- **Шаг за шагом, без корутин.** `Expedition.Advance()` — один час; на развилке возвращается `ExpeditionDecision` с вариантами, UI его только рисует и отдаёт выбор обратно. Отдельных типов-событий (`Found`, `Killed`, `Migrated`) нет — наружу идут решения и строки лога. Логика не знает, что её показывают.
- **Состояние — данные.** Лес, отряды, люди, склад — плоские структуры, которые можно сериализовать и сравнить в тесте на равенство.

## 7. Хот-релоад

Горячей перезагрузки таблиц в игре пока нет: CSV читаются один раз при старте. Перечитывание на границе дня (`R`) — план, не реализация; правки данных сейчас требуют перезапуска Play Mode.

## 8. Тесты и прогоны

| Инструмент | Что проверяет |
|---|---|
| `sim --selfcheck` | все проверки ядра, код возврата ≠ 0 при провале |
| `sim --days 21` | таблица дней: частокол, волна, гнёзда, твари; пассивный прогон, сид зашит (2026) |
| `sim --days N` | любое число дней тем же пассивным прогоном |

Отдельных `--validate`, `--seed` и `--roster` нет: проверки схемы идут внутри `--selfcheck`, сид зашит. EditMode-тестов Unity в проекте нет — все проверки живут в `tools/sim`.

Проверки утверждают и инварианты, и конкретные числа: «за 21 день без вмешательства появляется гнездо», «волна не приходит раньше своего дня», но и «рабочих часов 9», «частокол после пассивной волны 4/10». При правке баланса их приходится обновлять.

## 9. Что дальше

Порядок работы: загрузчик и валидатор → чистое ядро суток и леса → консольный прогон → сцена и UI → отряды. Сцена подключается последней, потому что до неё всё проверяется тестами без редактора.

## 10. Шаг 1: что уже работает

Проект Unity живёт в `FG/`, документация — в корне репозитория. Проектирование интерфейса
(экраны цикла суток, отряды-пресеты, карты событий вылазки) — в `docs/ui.md`.

| Что | Где | Чем проверено |
|---|---|---|
| 17 CSV-справочников (15 данных + 2 сценария) | `FG/Assets/StreamingAssets/Data/` | `dotnet run --project tools/sim -- --selfcheck` |
| Загрузчик с валидацией внешних ключей | `FG/Assets/Scripts/Core/Data/` | проверки «сломанный сосед», «неизвестный предмет», «чужая schema_version» |
| Ядро: `Rng`, `World`, `NightSim`, `DayPlan`, `Expedition`, `ExpeditionSim`, `ExpeditionResult`, `DayFlow`, `WaveSim`, `Briefing`, `Works`, `ZoneKnowledge`, `State` | `FG/Assets/Scripts/Core/Sim/` | 34 проверки в `tools/sim`, ядро без `UnityEngine` |
| Карта, досье зоны, экраны цикла, отчёт | `FG/Assets/UI/`, `FG/Assets/Scripts/Game/` | скриншоты `docs/images/ui/step1/` |
| Кит интерфейса: золотая плашка, палитра | `FG/Assets/UI/Art/Kit/`, `Map.uss` | скриншоты меню и модала встречи |
| Сцена | `FG/Assets/Scenes/Main.unity` | Play Mode, день 1 → отчёт → день 2 |

Сборка сцены — скриптом `FG/AgentScripts/BuildScene.cs` через `unity command script run` (файл вне `Assets/`, поэтому не тянет импорт). Ссылку `PanelSettings` пришлось ставить через `SerializedObject`: сеттер `UIDocument.panelSettings` в скриптовой сборке сцены не сериализовался (`m_PanelSettings: {fileID: 0}`), из-за чего экран был чёрным.

### Слои UI-кода

`Assets/Scripts/Game` разделён по одной ответственности:

| Класс | Что делает |
|---|---|
| `Scenario` → `Episode` | ядро: сценарий из CSV задаёт сид, день, отряды и стартовый экран; `EpisodeBuilder.Build` собирает мир |
| `MapScreen` | запускает эпизод, переключает фазы, показывает приказ и ночной отчёт |
| `HudView` | верхняя строка (день, фаза, частокол, волна, склад, здоровы) |
| `StartOfDayScreen` | окно начала дня: номер дня и статус жителей |
| `DossierScreen` | полноэкранное досье зоны (правая панель-превью убрана) |
| `MorningBoard` | экран планирования: карточки отрядов и предупреждения |
| `VillageScreen` | окно деревни: частокол, работы, кто где |
| `ExpeditionScreen` | поход: часы, лог, карточка развилки, пауза и «домотать» |
| `MusterScreen` | Сбор отряда: гильдии, лоток, наказы |
| `EveningScreen` | вечер: склад с дельтой, постели, сон |
| `Assignment` | кто где занят — правило ядра: человек — одно дело в день |
| `Ui` | мелкие фабрики: метка с классом, портрет жителя |
| `MapController` + `ZoneNodeView` + `EdgeLine` | карта: узлы по `map_x/map_y`, рёбра, деревня |

Данные: `Tables` вынесен в отдельный файл от `DataLoader` — справочники как объект и их загрузка/валидация больше не в одном месте.

**Эпизоды.** Любой запуск мира — это `scenarios.csv` (+ `scenario_parties.csv`): сид, день, стартовый экран (`campaign` / `muster` / `expedition`), что делать по завершении (`continue` / `menu`) и кто куда идёт. `EpisodeBuilder.Build(tables, id)` собирает `Episode` = мир + план + сид + сценарий. «Начать игру» и тестовые пункты меню — строки одной таблицы, а не ветки кода; добавить эпизод = добавить строки, без компиляции.

`AgentScripts/` (вне `Assets/`) — одноразовые пробы для проверки экранов через `unity command script run`; в игру не попадают.
